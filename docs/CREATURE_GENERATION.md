# 三件孵化与现场演示

2026-09-23：当前玩家入口为“孵化整只”。玩家一次输入头、身体、脚的描述；DeepSeek 一次生成三件相协调的名称、说明和英文 3D 提示词；Tripo 为每件创建独立异步任务。三件 GLB 保存到本机 `.runtime/models` 后，一次应用到当前三个已解锁蓝图，随后进入原有战斗。

服务端只读取项目根目录 `.env.local`，密钥不放入浏览器或仓库。2026-09-23 在 `127.0.0.1:3018` 完成一次真实端到端试玩：DeepSeek 返回三件 `DEEPSEEK` 草案；Tripo 三个任务各生成并下载一件 GLB；组装页显示头、身、脚三件“GLB 已载入”；使用该造物打赢第一场，缴获钻角头；刷新后造物、蓝图和战绩仍在。另一次独立 Tripo 单件任务验证了原任务编号恢复查询和本机 `/api/models/<id>` 返回模型。当前下载允许 Tripo `tripo3d.ai` 和 `tripo3d.com` 旗下 HTTPS 域名；其他确属供应商的 CDN 精确主机名才填 `TRIPO_ASSET_HOSTS`。

演示时先从“孵化整只”提交三件任务，页面分别显示进度和本地/Tripo 任务编号。等待期间可介绍蓝图、战斗和传承；切回孵化页会按已保存编号继续查询。三件全部成功后点击“装配整只怪物并出战”，在组装页旋转查看，再打第一场。现场网络失败时使用已经导入的九件队友 GLB 继续可玩流程，并明确说明哪些是预置素材、哪些是现场生成。

已知边界：本次真实生成的机械造物可见、可战斗，但头、身、脚之间仍能看出拼装接缝；独立生成无法保证任意描述都无缝拼接。当前按部件包围盒缩放到三个锚点；生成外观尚不改变数值或技能，因此 NEW LIFE 赛道的“生成式玩法深度”仍有缺口。当前只监听本机 127.0.0.1，不能直接把 localhost 链接交给异地评委。公开仓库、可访问 Demo 链接和参赛成员材料仍须按赛事提交入口检查。

## 2026-09-23 已确认的下一轮改造顺序

以下是与用户确认的当前基线顺序。收到游戏专家建议后，先合并评估再决定最终实施顺序；此记录不表示下面的功能已经完成。

1. **朝向和装配质量**：统一头、身体、脚的前向约定；先用已有生成 GLB 验证四面预览、逐件转向与连接点校准。正面或接缝未通过验收时，不把“GLB 已载入”称为“完整造物”；无法校准的部件需重新生成或换用预置素材。
2. **缓存和造物库**：在已有 `.runtime/models` 文件缓存与浏览器进度的基础上，保存每只造物的三件模型编号、描述、校准变换和缩略图，允许重开后直接选用而无需再次调用生成 API。异地演示还需持久的远程模型存储。
3. **玩家可操作的战斗技能**：现有战斗在开战时已预先算完，只播放结果。后续让玩家在回合中选择普通攻击、头部主动技能或防御，技能时机能改变战局；保存动作与状态，保证刷新后可恢复，保留旧存档兼容。
4. **专家点评后的前端方案**：先让游戏专家审视核心循环和界面，再结合 `operational-ui-polish` 的结构、状态、表单、响应式和可访问性检查形成方案。本技能面向浅色运营后台，其固定外壳和视觉语言与 ShellForge 现有深色游戏舞台冲突；不能未经评估把整套后台视觉直接覆盖到游戏。用户要求先出方案，不修改产品代码。
